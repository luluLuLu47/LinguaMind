# LinguaMind

基于大语言模型的多语言自适应学习智能体 —— 场景化 AI 口语陪练，边聊边纠、边纠边学。

面向"能读写、难开口"的语言学习者：现有工具里，题库型产品只覆盖输入、通用 AI 聊天有输出但没有教学策略。LinguaMind 用**双 Agent 协作**补上"自由输出 + 教学式反馈"这一环。

## 核心设计

### 双 Agent 职责分离

| Agent | 职责 | 输出 |
|---|---|---|
| 陪练 Agent（Practice） | 场景剧本注入、角色扮演、剧情推进 | 自然语言对话（SSE 流式） |
| 批改 Agent（Coach） | 语法/用词错误识别与分级 | 结构化 JSON 评分 |

拆成两个 Agent 而不是一个，是因为"自然对话"和"严格纠错"在同一个 Prompt 里目标冲突；拆分后两者可独立调整 Prompt、独立评估、独立替换模型。

> 当前实现是**串行编排**：陪练 Agent 的流式响应推送完毕后，再触发批改 Agent。因为批改输出必须是完整 JSON 才能解析，不适合流式。改造为真并行（`Promise.all` + 批改结果缓冲）是后续优化项，接口层无需变动。

### 纠错时机分级

即时纠错能强化记忆，但频繁打断会摧毁表达意愿。这是教学策略问题，不是技术问题：

| 错误类型 | 时机 |
|---|---|
| 重大语法错误（主谓不一致、时态） | 对话中即时纠正 |
| 轻微语法问题（冠词、介词） | 对话节点结束时集中反馈 |
| 发音不标准 | 对话结束后展示 |
| 用词不够地道 | 仅记录，进周报 |

MVP 阶段用规则兜底而非让 LLM 自主判断 —— LLM 对同一句话可能这次纠、下次不纠，行为不一致会让用户失去信任。

### 为什么没用 RAG

MVP 阶段的知识是几十到几百条的静态语法规则与场景剧本。这种情况下引入检索，是用检索的不确定性去解决一个不存在的规模问题。当前用 Prompt 注入，但知识来源已抽象为接口，数据量到千条量级时可无缝切换 RAG。

## 技术栈

- **框架**：Next.js 16（App Router）+ React 19 + TypeScript
- **数据**：SQLite（better-sqlite3，WAL 模式）+ repository 封装
- **模型**：DeepSeek-V3（对话/批改）+ 阿里云 Qwen-Turbo（辅助任务）混合调度
- **语音**：Whisper ASR + Edge-TTS
- **传输**：SSE 流式推送（对话流 + 批改流分阶段推送）
- **鉴权**：JWT + bcrypt
- **测试**：vitest

## 功能

场景化角色扮演对话 · 实时学习面板（错误/新词/准确率）· 语音输入与发音示范 · 生词本 · 发音入门（英 48 音标 / 韩 40 字母）· 每日一句与打卡 · 学习报告可视化 · 单词小游戏 · 账户体系 · 管理后台

英韩双语通过 language-context 做数据隔离。

## 本地运行

```bash
npm install
cp .env.example .env.local   # 填入 LLM / ASR 相关配置
npm run dev
```

打开 http://localhost:3000

单元测试：

```bash
npm test
```

> 数据库文件在首次运行时自动创建，已排除在版本控制之外。
